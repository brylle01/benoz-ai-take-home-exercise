● Done. The site is built and the production bundle serves correctly.

  What's there

  starterpackage/site/ — React 18 + Tailwind CSS v4 + Vite, ~250 lines of app
  code across four files.

  The important design choice: no submission content lives in JSX. src/App.jsx
  imports four markdown files via Vite's ?raw:

  starterpackage/submission/part1-handover-review.md   ← your existing review,
  wired in
  starterpackage/submission/part2-code.md              ← stub
  starterpackage/submission/part3-decisions.md         ← stub
  starterpackage/submission/part4-ai-usage.md          ← stub

  Edit those files and the page updates. You never touch React to finish the
  submission.

  Page structure: header with the four parts as cards → sticky nav bar that
  highlights the section you're in (IntersectionObserver) → the four parts
  rendered as cards, with GFM tables, fenced code blocks, and heading anchor IDs
  so you can deep-link.

  Parts 2–4 are stubs

  Only Part 1 existed in the repo. I created the other three as markdown
  skeletons with TODO markers and the right headings — Part 2 has the repo-link
  and "what changed" scaffold, Part 3 has the what-I-chose / why /
  what-I-gave-up shape three times, Part 4 has a transcript table. I left the
  three decisions' titles blank because the exercise brief isn't in this repo,
  so I don't know what they are.

  Publishing

  - GitHub Pages — .github/workflows/deploy-pages.yml builds and deploys on push
    to main. Enable once under Settings → Pages → Source → GitHub Actions.
  - Netlify — netlify.toml at the repo root, already pointed at the right
    subdirectory.
  - Vercel — starterpackage/site/vercel.json; set root directory to
    starterpackage/site.

  base: './' in the Vite config means the build works at any URL path, so a
  Pages project site won't break asset loading.

  cd starterpackage/site && npm run dev

  What I verified

  npm run build succeeds (294 modules, 3.7s), the Part 1 prose is present in the
  emitted bundle, Tailwind generated the styles, and npm run preview serves the
  HTML with both assets returning 200. I did not open it in a browser, so I
  haven't visually confirmed the rendering — worth a look at npm run dev before
  you deploy.
